選中樞先問三個問題：斷網後還能不能用？跨閘道的場景能不能執行？換品牌時設備和帳號能不能帶走？ 三個都過關，才值得把全屋掛上去。

一、雲依賴：斷網就癱瘓#

只支持雲端執行的中樞，在斷網、廠商伺服器故障、App 下架時會直接失效。判斷方法：

  • 拔掉外網，測試開關燈、開合窗簾、場景執行是否仍可用。
  • 詢問「本地執行」是全部自動化還是僅部分場景。
  • 看平臺是否有本地閘道/本地伺服器形態的產品線。

二、閘道孤島：跨閘道場景不生效#

一個家裡裝 3 個閘道很常見，但如果它們各自為政：

  • 「樓下關燈 + 樓上開窗簾」這類跨閘道場景無法執行。
  • 設備命名混亂，排查困難。
  • 家庭成員的權限無法統一。

解法：選擇能統一納管多閘道的上層中樞，或採用同一品牌的多閘道統一平臺。

三、Matter 控制器 vs Matter 橋接#

  • 控制器（Controller）：能直接納管 Matter 設備，是真正的中樞。
  • 橋接（Bridge）：把自家私有設備「翻譯」成 Matter 暴露給其他生態，功能常被裁剪（如場景、多鍵面板自定義）。
  • 選購時確認：它支持 Matter 1.4+ 的哪幾類設備（燈、窗簾、感測器、門鎖支持進度不同）。

四、私有協定鎖死#

風險信號：

  • 設備只能通過自家 App 控制，無本地 API。
  • 閘道不與第三方生態互通。
  • 帳號體系強綁定手機號，換號/換地區受限。

降低風險的做法：關鍵執行層（燈光、窗簾）優先選擇同時支持 Matter 或開放本地介面的產品，把廠商差異留在感測器這類低價值設備上。

五、容量、供電與散熱#

  • 消費級閘道穩定帶 40–60 個設備比較穩妥，別墅/大平層建議按樓層分區接入。
  • 閘道要常供電，不要插在會被隨手關掉的插排上。
  • 弱電箱內閘道溫度高會頻繁重啟，金屬箱體 + 通風孔 + 移出大功率設備。

六、升級與售後#

  • 固件更新頻率：長期不更新的平臺，兼容性問題會累積。
  • 雲服務生命周期：詢問廠商的「服務下線提前通知期」。
  • 數據導出：是否支持導出設備清單與場景配置。

不要把門鎖、報警器、燃氣探測這類安全相關設備託付給一個只支持雲端的平臺。安全功能必須斷網可用。

還有疑問？

一個中樞夠嗎？

建議兩條路線冗餘，例如「品牌中樞 + 自建本地中樞」，或「主中樞 + 備用閘道」。成本增加有限，能避免中樞故障導致全屋癱瘓。

Home Assistant 值得上嗎？

適合願意投入時間、追求本地控制與高度自定義的用戶。代價是需要自行維護（備份、更新、故障排查）。建議只在次要功能上先試用，穩定後再納入關鍵場景。

怎麼測試中樞是不是本地控制？

斷開區域網出口（拔掉光貓到路由的網路線），然後測試：面板控制燈、場景執行、窗簾開合、門鎖開門記錄。能用的部分就是本地能力。
