Matter 不是萬能協定，它是「應用層標準」：它統一了設備怎麼被控制，但沒有統一設備怎麼組網（底層仍是 Wi-Fi、Thread 或乙太網）。工程上最穩的搭配是：主幹走有線（網路線/RS485），感測器與控制走 Zigbee/Thread，少數高帶寬設備用 Wi-Fi。

二、Matter 到底解決了什麼#

  • 解決了：跨生態互通（一個設備可被 Apple 家庭、Google、Alexa、自家 App 同時控制）、本地控制與多管理員機制。
  • 沒解決：底層組網仍需 Thread/Wi-Fi；高級功能（多鍵面板的自定義、燈光的複雜場景、窗簾的微調）往往要走廠商私有通道；不同生態對同一設備的支持程度不一致。

實用判斷：Matter 是「入場券」，不是「能力清單」。買設備時看它支持 Matter，更要看它在本地控制、離線可用、功能完整度上的表現。

三、Thread 與邊界路由器#

Thread 設備需要 Border Router 才能接入網路。現實中它常由智慧音箱、中樞、路由器內置實現。注意事項：

  • 家裡至少要有 2 個 Border Router（冗餘），否則單點故障會導致整個 Thread 網路掉線。
  • Thread 網路依賴穩定的 IPv6 與 mDNS，部分老路由器需要手動開啟相關功能。
  • Thread 目前設備品類仍不如 Zigbee 豐富，重感測器場景 Zigbee 更成熟。

四、Wi-Fi 設備的數量陷阱#

Wi-Fi 智慧設備便宜、免閘道，很適合補充，但要注意：

  • 家用路由器對單頻 2.4GHz 的並發設備通常只能穩定支持 30–50 臺。
  • 大量廉價 Wi-Fi 設備會持續拉低空口效率，影響手機上網體驗。
  • 建議：全屋帶通信功能的設備超過 40 臺時，就把燈光、感測器、窗簾換成 Zigbee/Thread。

五、有線：什麼時候值得花這個錢#

  • 大平層、別墅、對穩定性零容忍的場景（酒店客房、樣品屋、高端住宅）。
  • 燈光迴路多、需要確定無延遲調光時（0-10V / DALI / KNX）。
  • 暖通、地暖、新風、遮陽一體化控制。
  • 換算：有線方案每迴路成本通常比無線高 1.5–3 倍，但故障率顯著更低，且可年限很長。

六、推薦的混用策略#

  1. 網路與主幹：CAT6A + PoE，有線到底。
  2. 燈光：輕量無線（Zigbee）+ 關鍵區域有線調光。
  3. 感測器：Zigbee/Thread，電池供電優先，減少點位電源壓力。
  4. 大件家電：優先乙太網或本地介面（RS485/幹接點），紅外只作補充。
  5. 中樞：至少兩條路線冗餘（例如自建本地中樞 + 主流生態），避免單生態鎖死。

不要因為某個品牌便宜，就把全屋燈光、窗簾、門鎖全部壓縮到它自己的私有協定裡。協定鎖定之後，一次漲價、一次 App 下架、一次伺服器遷移，都會變成你的成本。

還有疑問？

Matter 設備能在沒有網路時工作嗎？

取決於生態實現。Matter 支持本地控制，理論上斷網後同一區域網內的 App 或中樞仍可控制；但雲端語音助手會失效。選購時明確問一句「斷網後能不能用、哪些功能會失效」。

Zigbee 和 Thread 會互相干擾嗎？

兩者都在 2.4GHz 頻段，與 Wi-Fi 同頻。建議把 Wi-Fi 的 2.4GHz 固定在 1、6、11 中表現最好的信道，並讓 Zigbee/Thread 選擇與之錯開（例如 15、20、25）的信道。

一個閘道最多帶多少設備？

廠商標稱往往樂觀。實測經驗：消費級閘道穩定帶 40–60 個設備比較合理，超過後響應變慢、掉線率上升。大型住宅建議按樓層或區域分多個閘道，並確保跨閘道場景可用。
